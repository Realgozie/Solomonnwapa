# Solomon Nwapa — CEO of Cent22 Intelligence

A responsive professional website and software portfolio built with the Next.js
App Router, TypeScript, and Tailwind CSS. It has no database, backend service,
analytics dependency, paid API, or Replit-specific runtime package.

Solomon Nwapa is presented as CEO of Cent22 Intelligence and an Enterprise &
Digital Software Developer. Company services, history, customers, and results
are not described unless confirmed.

## Pages

- `/` — professional introduction and featured projects
- `/about` — professional positioning and vision
- `/work` — project index
- `/work/adboss` and `/work/novasplit` — project profiles
- `/capabilities` and `/industries` — areas of focus and interest
- `/insights` — publication landing page with an honest empty state
- `/contact` — verified contact methods when configured

The legacy `/projects/adboss` and `/projects/novasplit` paths redirect to their
canonical `/work/...` URLs.

## Requirements and local development

- Node.js 20.9 or newer
- npm 10+ or pnpm 9+

### In this repository

From the repository root:

```bash
pnpm install
pnpm --filter @workspace/solomon-nwapa run dev
```

Useful checks and commands:

```bash
pnpm --filter @workspace/solomon-nwapa run typecheck
pnpm --filter @workspace/solomon-nwapa run build
pnpm --filter @workspace/solomon-nwapa run start
```

### As a standalone project

Copy this folder to another computer or open it in Cursor. The standalone
`package-lock.json` is included:

```bash
npm ci
npm run dev
```

The `pnpm-lock.yaml` in the repository root is used when working in the original
pnpm workspace; `package-lock.json` is used for the standalone npm workflow.

## Personalize the site

### Personal information and contact links

Edit `src/content/site.ts` to update all shared professional identity and site
copy:

- `name`, `title`, `organizationName`, and `organizationRole`
- `description`, `headline`, and editable page copy under `pages`
- `biography` (leave it `null` until a fact-checked biography is supplied)
- `email` (only add an address intended for public contact)
- `profiles.linkedin` and `profiles.github` (only add verified HTTPS profile URLs)
- `images.heroPortrait`, `images.aboutPortrait`, and
  `images.professionalPortrait` after adding the approved photographs
- `images.socialImage` for an optional custom sharing image

Unknown personal details remain `null`. No biography, email, profile, Cent22
company facts, client, testimonial, metric, project capability, technology
stack, or project outcome has been invented. Contact does not display a fake
message form.

### Project profiles

Edit these separate files directly; no additional authoring service or AI task
is needed:

- `src/content/projects/adboss.ts`
- `src/content/projects/novasplit.ts`

Each file has fields for a verified summary, problem, intended audience,
implemented capabilities, technology stack, development approach, local
screenshots, and a verified live URL. Optional fields start as `null` or empty
arrays and do not produce blank labels on the site. Keep unconfirmed claims out.

### Images

See `public/images/README.md` for the asset locations:

- `public/images/profile/solomon-hero.jpg` — homepage hero portrait
- `public/images/profile/solomon-about.jpg` — About portrait
- `public/images/profile/solomon-professional.jpg` — additional professional
  photo on the About page
- `public/images/projects/adboss/` and `public/images/projects/novasplit/` —
  confirmed project screenshots
- `public/images/og/solomon-nwapa.png` — optional custom social image

For the three personal photos, set the corresponding `src` and descriptive
`alt` fields in `src/content/site.ts`; the photo placeholders remain in place
until both the file and configuration are added. Project screenshots also need
their pixel width, height, and accurate alt text in the corresponding project
data file. The default social image is generated by the app. A custom image
should be at least 1200×630 pixels and must exist before setting
`images.socialImage` in `src/content/site.ts`.

### Manual updates when details are ready

All content can be edited directly in the listed files:

1. Add the three approved photographs to the exact paths above, then set
   `images.heroPortrait`, `images.aboutPortrait`, and
   `images.professionalPortrait` (`src` and `alt`) in
   `src/content/site.ts`.
2. Add the approved biography in `biography`, a public email in `email`, and
   verified professional URLs in `profiles.linkedin` and `profiles.github` in
   `src/content/site.ts`. Edit page copy in that same file.
3. Add confirmed AdBOSS details in `src/content/projects/adboss.ts` and
   NovaSplit details in `src/content/projects/novasplit.ts`.
4. Optionally add a custom social image and set `images.socialImage` in
   `src/content/site.ts`.

No backend, database, paid API, or separate editing tool is needed for these
updates.

## SEO and domain configuration

The app includes page-specific titles and descriptions, canonical URL support,
Open Graph and Twitter cards, a dynamic `sitemap.xml` and `robots.txt`, and
Schema.org `Person`, `ProfilePage`, `WebSite`, and project `CreativeWork` data.
Structured data includes only the details configured in the content files. SEO
metadata improves discoverability but cannot guarantee search rankings.

Set the public base URL through the single `NEXT_PUBLIC_SITE_URL` environment
variable. Copy `.env.example` to `.env.local` for local testing if needed. On
Vercel, the deployment URL is used as a fallback when the variable is unset.

1. Start with the exact temporary URL assigned by Vercel, such as
   `https://your-project.vercel.app`.
2. Set `NEXT_PUBLIC_SITE_URL` for the Vercel Production environment and deploy.
3. When a custom domain is connected, change the value to that domain’s HTTPS
   origin, then redeploy.

Do not leave an example domain in the setting. The app uses the configured
origin for canonical URLs, structured data, and sitemap/robots links.

## Deploy to Vercel

1. Import the Git repository into Vercel.
2. Set the Root Directory to `artifacts/solomon-nwapa`.
3. Select Next.js as the framework preset.
4. Set `NEXT_PUBLIC_SITE_URL` to the current public HTTPS domain.
5. Deploy, then use Vercel’s domain settings to add a custom domain when ready.
   Update `NEXT_PUBLIC_SITE_URL` and redeploy after switching domains.

The project uses standard Next.js conventions and can be installed and deployed
without Replit hosting APIs or a separate backend.
